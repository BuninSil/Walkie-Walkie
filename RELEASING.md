# Как выпускать обновления рации и радиостанции

Гайд для тех, кто правит код и выпускает новые версии Android-приложений:
**Рация** (`android/`) и **Радиостанция** (`radio-air/`).

Выпущенный релиз телефоны находят сами: приложения проверяют
[релизы репозитория](https://github.com/BuninSil/Walkie-Walkie/releases) при каждом входе и раз в 6 часов в фоне,
скачивают APK и ставят поверх. Чтобы это сработало, у релиза должны совпасть три вещи (всё делает кнопка из шага 3):

| Что | Правило | Почему |
|---|---|---|
| Имя файла | `Walkie-1.0.N.apk` (рация) или `Station-1.0.N.apk` (станция) | по имени приложение понимает, что это его обновление и какая версия |
| Номер `N` | больше, чем у последнего выпуска этого приложения | Android не ставит версию ниже установленной, приложение такую даже не предложит |
| Подпись | постоянный ключ `walkie-release.p12` | APK с другим ключом Android не поставит поверх — только удалять и ставить заново, с потерей настроек |

Текст релиза начинается с `## Новое в 1.0.N` и пунктов `- …`. Эти пункты приложение показывает
в плашке «Что нового» после обновления.

---

## Шаг 1. Один раз: владелец добавляет ключ в секреты

Делает владелец репозитория (BuninSil) один раз. Сам ключ в репозиторий **не кладётся никогда**:
репозиторий публичный, а с ключом кто угодно выпустит «обновление» на ваши телефоны.

1. Открыть репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
2. Добавить два секрета. Значения лежат в файле `WALKIE-SECRETS.txt`, который ты получил вместе с ключом:
   - `WALKIE_KEYSTORE_PASSWORD`: пароль ключа;
   - `WALKIE_KEYSTORE_BASE64`: ключ `walkie-release.p12` в base64, **одной строкой, целиком**.

   Если base64 надо сделать заново из `walkie-release.p12`:
   - Windows (PowerShell): `[Convert]::ToBase64String([IO.File]::ReadAllBytes("walkie-release.p12")) | Set-Clipboard`, дальше вставить из буфера.
   - Linux/macOS: `base64 -w0 walkie-release.p12` (на macOS просто `base64 -i walkie-release.p12`).
3. Дать другу доступ: **Settings → Collaborators → Add people** → его ник на GitHub.
   Роль **Write**: этого хватает, чтобы пушить код и запускать выпуск.
   Друг должен принять приглашение из почты или уведомлений GitHub.

После этого секреты видны только сборкам GitHub Actions. Ни друг, ни кто-то ещё прочитать их не сможет,
только пользоваться ими через сборку.

> `walkie-release.p12` и пароль храните ещё и у себя (облако, флешка). Если ключ потерять,
> выпускать обновления поверх установленных приложений будет нечем.

## Шаг 2. Внести изменения в код

Самый простой путь — прямо на GitHub:

1. Открыть файл на github.com → карандаш ✏️ (**Edit this file**).
2. Поправить → **Commit changes…** → в `main` (или в свою ветку, если хочешь сначала проверить).

Или локально:

```bash
git clone https://github.com/BuninSil/Walkie-Walkie.git
cd Walkie-Walkie
# правки…
git add -A
git commit -m "Что поменял"
git push
```

Где что лежит:

| Что меняем | Где |
|---|---|
| Рация: Android-обёртка (уведомление, кнопка поверх, экран блокировки, обновления) | `android/app/src/main/java/ru/radio/walkie/` |
| Рация: настройки ⚙, внешний вид 🎨, фонарик/SOS, «Что нового» | `android/app/src/main/assets/android/` (`bridge.js`, `look.js`, `look.css`, `android.css`) |
| Рация: сама рация (экран, кнопки, звук, эфир) | `radio-walkie/web/`: общая с ПК-версией, правка меняет обе |
| Станция: логика эфира, плейлист, декодер | `radio-air/app/src/main/java/ru/radio/station/` |
| Станция: интерфейс | `radio-air/app/src/main/assets/ui/` (`index.html`, `app.js`, `style.css`, `look.js`, `look.css`) |

После каждого пуша GitHub сам собирает проверочную сборку (Actions → «Android APK» / «Station APK»).
Зелёная галочка значит, что код собирается. Эти сборки **не** релизы: телефоны их не видят.

> ⚠️ `radio-walkie/web/` — общий код с ПК. Если сломать там протокол эфира, ПК и телефоны перестанут слышать друг друга.
> Правки в эфир (`air-server.js`, формат пакетов, шифрование) проверяйте на ПК и на телефоне одновременно.

## Шаг 3. Выпустить релиз: одна кнопка

1. Репозиторий → вкладка **Actions** → слева **«Выпустить релиз»** → справа **Run workflow**.
2. Заполнить:
   - **Use workflow from**: ветка, из которой собирать (обычно `main`);
   - **Что выпускаем**: `walkie` (рация) или `station` (радиостанция);
   - **Что нового**: пункты через точку с запятой, например
     `Починил звук в наушниках; Новая тема «Пустыня»; Антенна подлиннее`.
3. **Run workflow**. Через 4–6 минут в [Releases](https://github.com/BuninSil/Walkie-Walkie/releases) появится
   `Рация 1.0.N` / `Радиостанция 1.0.N` с APK.

Кнопка всё делает сама:

- номер версии: берёт последний выпуск этого приложения и прибавляет 1;
- сборку release-APK;
- подпись ключом из секретов, с проверкой, что ключ тот самый (отпечаток `E7:DD:C0:8B…73:B2`);
- текст релиза `## Новое в 1.0.N` с твоими пунктами;
- публикацию релиза.

Дальше ничего не надо: телефоны подхватят обновление при следующем входе в приложение
(или в течение 6 часов в фоне). Вручную: рация → ⚙ → «Обновления» → «Проверить»; станция → блок «Обновления» внизу.

Рацию и станцию выпускают отдельно, номера у них свои. Изменил только станцию — выпускай только `station`.

### Если сборка красная

Открыть упавший запуск → упавший шаг, там текст ошибки.

| Ошибка | Что делать |
|---|---|
| «нет секретов WALKIE_KEYSTORE_BASE64 и WALKIE_KEYSTORE_PASSWORD» | не сделан шаг 1: владелец добавляет секреты |
| «не тот ключ подписи» | в секрете другой ключ или base64 обрезан. Вставить заново, одной строкой |
| `keytool error: … password was incorrect` | неверный `WALKIE_KEYSTORE_PASSWORD` |
| ошибка в шаге «Собрать и подписать» (`error:` в `.java`) | ошибка в коде. Исправить, запушить, запустить кнопку снова |
| Нет кнопки **Run workflow** | нет прав Write (шаг 1, пункт 3) или workflow смотрят не в `main` |

Упавший выпуск ничего не публикует. Номер не «сгорает», следующий запуск возьмёт тот же `N`.

## Удалить неудачный релиз

Выпустил с ошибкой — просто выпусти следующий с исправлением. Номер будет больше, и телефоны обновятся на него.

Сам релиз можно удалить: **Releases → релиз → 🗑 Delete**, а потом **Tags** → тот же тег → **Delete**.
Удалённый релиз телефоны больше не предложат. Кто успел поставить, останется на нём до следующего выпуска
(версию ниже Android не поставит).

## Как проверить обновление на телефоне

1. Стоит старая версия (видно в ⚙ → «Обновления» у рации, внизу экрана у станции).
2. Выпустить новую (шаг 3).
3. Закрыть и открыть приложение: появится «Доступно 1.0.N» и начнётся загрузка.
   В первый раз Android попросит «Разрешить установку из этого источника»: разрешить и вернуться в приложение.
4. После установки приложение откроется с плашкой «Что нового» и твоими пунктами.

Рация не ставит обновление во время передачи, станция — во время эфира. Обновление подождёт.

## Запасной путь: собрать и подписать у себя

Если Actions недоступны. Нужен ключ `walkie-release.p12` и пароль, поэтому это делает тот, у кого они есть.

1. Поставить **JDK 17+** и **Android Studio** (или Android SDK command-line tools).
2. Собрать с подписью. Номер `N` = последний выпуск этого приложения + 1:

   ```bash
   # Linux/macOS
   export WALKIE_KEYSTORE_FILE=/путь/к/walkie-release.p12
   export WALKIE_KEYSTORE_PASSWORD='пароль'
   export WALKIE_BUILD_NUMBER=N
   cd android      # или radio-air для станции
   ./gradlew assembleRelease
   ```

   ```powershell
   # Windows PowerShell
   $env:WALKIE_KEYSTORE_FILE="C:\путь\к\walkie-release.p12"
   $env:WALKIE_KEYSTORE_PASSWORD="пароль"
   $env:WALKIE_BUILD_NUMBER="N"
   cd android      # или radio-air
   .\gradlew.bat assembleRelease
   ```

   Готовый APK: `app/build/outputs/apk/release/app-release.apk`.
   Переименовать в `Walkie-1.0.N.apk` / `Station-1.0.N.apk`.
3. Если APK собрался неподписанным (`app-release-unsigned.apk`), подписать тем же ключом:
   `python android/tools/sign_v2.py app-release-unsigned.apk Walkie-1.0.N.apk walkie-release.p12 ПАРОЛЬ`
   (нужен `pip install cryptography`).
4. Выложить: **Releases → Draft a new release**:
   - тег `v1.0.N` для рации или `station-v1.0.N` для станции;
   - заголовок `Рация 1.0.N` / `Радиостанция 1.0.N`;
   - текст начинается с `## Новое в 1.0.N`, дальше пункты `- …`;
   - APK прикрепить файлом;
   - **Publish release**.

## Коротко

1. Владелец один раз: секреты `WALKIE_KEYSTORE_BASE64` + `WALKIE_KEYSTORE_PASSWORD` и друг в Collaborators (Write).
2. Друг: правит код → пушит в `main` → Actions → «Выпустить релиз» → `walkie`/`station` + что нового → Run.
3. Телефоны обновляются сами.
